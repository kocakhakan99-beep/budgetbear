# Contributing to BudgetBear

Thanks for contributing! This document explains how to set up a dev environment, the workflow, and how to submit contributions.

Getting started
- Fork the repo and create feature branches from main: `git checkout -b feat/short-description`.
- Follow coding style: HTML/CSS/JS with clear comments and small commits.

Development workflow
- Open a PR to the main branch (or the repository's canonical development branch).
- Use small, focused commits and provide a clear PR description with motivation, changes, and screenshots if UI changes.
- Manually verify new behavior in a browser (see DEVELOPMENT.md).

Code quality
- Run the manual validation steps in DEVELOPMENT.md before opening PRs.
- Keep feature branches rebased on the target branch to minimize merge conflicts.

Issue reporting
- Use the issue template (GitHub) and provide steps to reproduce, expected vs actual behavior, browser and OS.

Security issues
- For security disclosures, see SECURITY.md.
